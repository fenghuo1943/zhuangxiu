# 装修日记功能开发文档

> 适用范围：在“辅助工具”中新增“装修日记”功能，记录装修过程中的阶段、日期、文字和现场图片。  
> 技术栈：React 19 + TypeScript + Vite、FastAPI + SQLAlchemy、现有登录认证与项目数据体系。  
> 参考实现：[TipsPage](../frontend/src/pages/TipsPage.tsx)、[tips API](../frontend/src/api/tips.ts)、[Tip 模型](../backend/models.py)以及采购清单页面的阶段数据结构。

---

## 1. 产品目标与范围

### 1.1 功能目标

用户可以在当前装修项目下创建、查看、编辑和删除装修日记，用日记记录某一天、某个装修阶段发生的施工进展、现场问题、验收结果或心得，并通过图片保留现场资料。

### 1.2 本期范围

- 在“辅助工具”导航中新增“装修日记”入口。
- 新增装修日记列表页，支持日记数量统计、关键词搜索和装修阶段筛选。
- 支持新建日记：标题、日期、装修阶段、内容和多张图片。
- 支持编辑和删除已有日记。
- 图片上传后显示缩略图，并支持删除尚未保存或已保存的图片引用。
- 日记数据按当前装修项目隔离，并要求用户登录。
- 日记列表按日期倒序排列，同一天可按创建时间倒序排列。

### 1.3 非本期范围

- 不实现评论、点赞、分享、公开发布和多人协作。
- 不实现富文本编辑器；首版内容使用多行纯文本，保留换行。
- 不实现图片裁剪、压缩、拖拽排序和视频上传。
- 不新增独立的阶段字典；阶段选项直接读取采购清单中的阶段分类。
- 不改变采购清单、装修流程和装修记账现有业务逻辑。

## 2. 页面信息架构

### 2.1 路由与导航

新增路由：

- 页面地址：`/diary`
- 页面名称：装修日记
- 导航分组：辅助工具
- 导航顺序建议：实用工具、装修日记、装修技巧、我的
- 页面壳层：继续使用现有 `AppShell`，桌面侧栏工作台和移动端底部导航均应正确高亮。

需要修改的主要位置：

- `frontend/src/App.tsx`：注册受保护路由。
- `frontend/src/components/layouts/workbenchNavigation.ts`：增加导航项及日记图标。
- `frontend/src/components/common/Icons.tsx`：复用 `IconBook` 或新增 `IconDiary`，图标需有可访问名称。

### 2.2 页面布局

页面从上到下分为四个区域：

```text
┌────────────────────────────────────────────────────┐
│ 装修日记                         共 N 篇   [写日记] │
├────────────────────────────────────────────────────┤
│ [搜索日记标题或内容……]       [全部装修阶段 ▼]     │
├────────────────────────────────────────────────────┤
│ 日记卡片                                           │
│  日期 · 阶段标签                                   │
│  标题                                               │
│  内容摘要                         图片数量 / 编辑  │
│                                                    │
│ 日记卡片                                           │
└────────────────────────────────────────────────────┘
```

#### 2.2.1 页头

- 左侧显示页面标题“装修日记”。
- 右侧显示日记总数量，例如“共 12 篇”。数量统计是当前项目全部日记数量，不受搜索和阶段筛选影响。
- 最右侧显示主按钮“写日记”。
- 主按钮必须有清晰文本、键盘焦点态和禁用态，不能只使用图标。

#### 2.2.2 搜索与阶段筛选

- 搜索框占主要宽度，提示文字为“搜索日记标题或内容……”。
- 搜索范围为标题和正文内容；建议前端输入防抖 300ms，后端仍需限制关键词长度。
- 阶段下拉框第一项为“全部装修阶段”。
- 阶段选项来自采购清单的阶段父分类，即 `purchaseReferences[].parent`，去重后保持采购清单原有顺序。
- 当采购清单尚未加载完成时，阶段筛选显示加载状态；加载失败时不能阻塞日记列表，可显示“阶段加载失败，请重试”。
- 搜索和筛选无结果时显示空状态“暂无符合条件的日记”，并提供“清除筛选”操作。

#### 2.2.3 日记列表

每篇日记以卡片展示：

- 日期：格式化为 `YYYY年MM月DD日`，并保留可读的阶段信息。
- 装修阶段：使用采购清单的阶段名称作为标签。
- 标题：最多两行，超出部分省略。
- 内容摘要：最多三行，保留换行语义；无内容时显示“暂无文字内容”。
- 图片：显示第一张图片作为封面；多图时显示图片数量。
- 操作：提供“编辑”和“删除”，删除前必须二次确认。
- 点击卡片主体可以打开编辑弹窗；点击按钮、图片预览时不得触发卡片打开事件。
- 没有任何数据时显示引导空状态：“还没有装修日记，记录下今天的装修进展吧。”，并提供“写第一篇日记”。

## 3. 写日记弹窗

点击“写日记”或空状态主按钮后打开弹窗；编辑已有日记时复用同一个弹窗和表单，不创建第二套表单逻辑。

### 3.1 表单顺序

必须按以下顺序展示：

1. **标题**：单行输入，必填，长度限制建议为 200 字符，提示“例如：水电验收记录”。
2. **日期**：日期输入，必填；新建时默认为当天，编辑时回填原日期。
3. **装修阶段**：下拉选择，必填；选项直接使用采购清单阶段父分类。新建时可默认当前项目阶段；若无法匹配采购阶段，则默认第一项并允许用户修改。
4. **内容**：多行文本域，选填，建议至少 6 行，长度限制建议为 10,000 字符，提示“记录施工进度、问题、验收结果或心得……”。
5. **上传图片**：支持 `jpg`、`jpeg`、`png`、`webp`，建议单张不超过 10MB，单篇最多 9 张。上传成功后显示缩略图、删除按钮和上传状态。
6. **底部操作**：左侧或次要按钮为“关闭”，主按钮为“保存”。编辑状态可额外显示“删除日记”，但删除必须使用危险色并二次确认。

### 3.2 弹窗交互

- 点击遮罩、关闭按钮或按 `Escape` 关闭弹窗；如果表单有未保存修改，应弹出确认提示，避免误丢内容。
- 保存时按钮进入加载状态并禁用，防止重复提交。
- 标题、日期、阶段校验失败时，在对应字段下显示错误信息，并将焦点移动到第一个错误字段。
- 保存成功后关闭弹窗、刷新当前列表和数量统计，并显示“日记已保存”。
- 保存失败时保留表单内容，在弹窗内显示可读错误，不清空用户输入。
- 上传中的图片不能提交保存；上传失败只影响当前图片，不应清空其他已上传图片。
- 图片预览支持点击放大；预览弹层同样支持 `Escape` 关闭。

### 3.3 图片上传策略

优先复用现有 `POST /api/upload/image` 的认证、文件类型校验和静态资源访问方式，但应评估其当前目录名 `flow-images` 是否适合通用图片。推荐后续抽象为通用上传目录或新增日记专用目录，避免日记图片与流程知识图片产生命名和清理耦合。

上传返回图片 URL 后，前端仅将 URL 放入表单状态；点击“保存”时一次性提交图片 URL 数组。删除日记或编辑时移除图片引用后，后端需要在确认图片没有被其他业务引用时再删除文件，不能直接删除可能被技巧或知识文章使用的公共文件。

## 4. 数据模型与业务规则

### 4.1 日记归属

装修日记属于项目，不属于用户全局数据：

- 一个用户可以有多个装修项目。
- 当前项目只能看到当前项目的日记。
- 用户不能通过修改 `project_id` 访问或编辑其他用户项目的日记。
- 删除项目时通过级联关系删除日记记录及其不再被引用的图片。

### 4.2 推荐数据模型

在 `backend/models.py` 新增 `RenovationDiary`：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `String(36)` | 主键 | 建议 `diary_` + 随机 ID |
| `project_id` | `String(36)` | 外键、非空、索引 | 所属装修项目 |
| `title` | `String(200)` | 非空 | 日记标题 |
| `date` | `Date` | 非空、索引 | 日记发生日期 |
| `stage_parent` | `String(100)` | 非空 | 采购清单阶段父分类名称 |
| `content` | `Text` | 非空，默认空字符串 | 日记正文 |
| `images` | `JSON` | 默认空数组 | 图片 URL 数组 |
| `created_at` | `DateTime` | 非空 | 创建时间 |
| `updated_at` | `DateTime` | 非空 | 更新时间 |

建议建立联合索引：

- `(project_id, date)`：支持项目日记按日期排序。
- `(project_id, stage_parent)`：支持阶段筛选。

`Project` 模型增加 `diaries` 关系，使用 `cascade="all, delete-orphan"`。数据库初始化采用现有幂等迁移方式新增表，不修改既有数据表，不把日记写入 `AppStateSync` 的旧本地状态字段。

### 4.3 阶段一致性

- 阶段来源的唯一业务依据是采购参考阶段的 `parent`。
- 创建和更新时，后端应校验 `stage_parent` 是否存在于采购阶段表；若产品允许历史阶段保留，可采用“允许保存但前端标记为历史阶段”的兼容策略，必须在实现前确定一种规则。
- 不建议使用装修流程的 `stage_key` 代替采购阶段名称，因为两者数据来源和粒度可能不同。
- 采购阶段名称发生变化时，历史日记是否同步改名应在后续版本单独设计；首版建议保存当时的名称快照，避免历史记录因参考库变化而失真。

## 5. 后端 API 设计

新增文件建议为 `backend/routers/diaries.py`，并在 `backend/main.py` 注册路由；数据结构写入 `backend/schemas.py`。

### 5.1 查询日记

`GET /api/projects/{project_id}/diaries`

查询参数：

- `stage_parent`：可选，阶段名称，最大 100 字符。
- `q`：可选，搜索标题或正文，最大 100 字符。
- `limit`：可选，默认 50，最大 100。
- `offset`：可选，默认 0；为后续分页预留。

返回：`DiaryOut[]`，按 `date DESC, created_at DESC` 排序。

权限要求：使用现有 `get_current_user` 和项目归属校验，只返回当前用户项目的数据。

### 5.2 创建日记

`POST /api/projects/{project_id}/diaries`

请求体：

- `title: string`
- `date: YYYY-MM-DD`
- `stage_parent: string`
- `content: string`，默认空字符串
- `images: string[]`，默认空数组

校验：标题、日期、阶段必填；标题、内容、图片数量和图片 URL 格式均需限制；图片 URL 应只允许本站上传资源路径，防止任意外链和脚本注入。

返回：HTTP `201` 和完整 `DiaryOut`。

### 5.3 更新日记

`PUT /api/projects/{project_id}/diaries/{diary_id}`

字段全部可选，但提交后必须保证完整数据仍满足创建规则。后端先验证日记属于当前项目，再更新记录。若图片数组发生变化，清理已移除且未被其他业务引用的图片文件。

### 5.4 删除日记

`DELETE /api/projects/{project_id}/diaries/{diary_id}`

先校验项目归属，再删除记录；图片文件只在跨表确认无引用后清理。返回 HTTP `204`。

### 5.5 数量统计

首版可以直接使用列表接口返回结果数量，或在前端维护 `diaries.length`。当加入分页后，新增：

`GET /api/projects/{project_id}/diaries/count`

返回：`{ "count": number }`，数量统计不受当前筛选条件影响。

## 6. 前端实现拆分

### 6.1 类型与 API

建议新增：

- `frontend/src/data/types.ts`：增加 `Diary` 类型。
- `frontend/src/api/diaries.ts`：封装列表、创建、更新、删除接口。
- 可复用现有 `api/client.ts` 的认证、超时、Token 刷新和错误处理。

建议的前端类型：

```text
Diary {
  id: string
  project_id: string
  title: string
  date: string
  stage_parent: string
  content: string
  images: string[]
  created_at: string
  updated_at: string
}
```

### 6.2 页面与组件

建议新增：

- `frontend/src/pages/DiaryPage.tsx`：页面数据加载、搜索筛选、弹窗状态和列表状态。
- `frontend/src/components/diary/DiaryCard.tsx`：日记卡片和摘要展示。
- `frontend/src/components/diary/DiaryModal.tsx`：新建/编辑共用表单。
- `frontend/src/components/diary/DiaryImageUploader.tsx`：图片选择、上传、缩略图和删除。
- `frontend/src/styles/diary.css`：日记页面及弹窗的独立样式。

页面应通过现有 `useStore()` 获取 `activeProjectId` 和采购参考数据，调用 API 时始终使用当前项目 ID。不要把服务端日记列表复制进全局 `store.ts`，除非后续明确需要首页“最近日记”模块。

### 6.3 阶段选项获取

- 复用采购清单已经加载的 `purchaseReferences`。
- 使用 `purchaseReferences.map(stage => stage.parent)`，通过 `Set` 去重。
- 阶段顺序保持采购清单顺序，不按字母排序。
- 如果当前项目没有采购参考数据，应提供明确空状态；不能静默生成与采购清单不一致的硬编码阶段。
- 当前项目阶段可以作为默认值，但默认值必须先与采购阶段名称匹配。

### 6.4 搜索策略

首版推荐服务端筛选，前端通过参数调用接口：

- `q`：标题或正文关键词。
- `stage_parent`：阶段名称。
- 搜索输入防抖 300ms。
- 筛选变化立即重新加载。
- 列表请求需要处理 loading、error、empty 三种状态。

若日记数量很少，也可以一次加载后在前端筛选，但必须保证切换项目时清空旧列表并重新加载，不能展示上一个项目的数据。

## 7. 样式与响应式规范

### 7.1 视觉风格

- 复用项目现有 `card`、`btn`、`input`、`modal-overlay`、`modal-header`、`modal-body`、`modal-footer` 等基础样式。
- 日记页保持浅暖灰背景、白色卡片、弱边框和圆角，不复制参考 HTML 的外部样式。
- 阶段标签使用主题语义色，不将颜色与阶段名称硬编码绑定。
- 图片采用固定比例缩略图，使用 `object-fit: cover`；图片加载失败时显示占位状态。

### 7.2 响应式

- 桌面端：页头标题、统计和写日记按钮同一行；搜索框与阶段筛选同一行。
- 平板端：允许筛选项换行，但按钮和输入仍保持可操作尺寸。
- 移动端：页头可换成两行，写日记按钮保持可见；搜索和阶段筛选纵向堆叠；日记卡片单列显示。
- 弹窗在窄屏使用接近全宽布局，内容区域可滚动，底部操作按钮始终可见。
- 页面不能出现横向滚动；图片网格在 320px 宽度下仍能正常展示。

### 7.3 无障碍

- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和可读标题。
- 打开弹窗后焦点进入标题输入框，关闭后焦点返回“写日记”按钮。
- 图片上传按钮必须有文本或 `aria-label`；缩略图删除按钮应包含“删除图片”及序号。
- 阶段筛选、保存、关闭、编辑、删除均使用原生按钮或表单控件。
- 颜色不能作为唯一状态表达方式，加载、错误、空状态都要有文字。

## 8. 错误处理与安全要求

- 未登录访问 `/diary` 时由 `ProtectedRoute` 拦截；API 仍必须进行后端认证校验。
- 项目 ID、日记 ID 不可信，所有读写接口必须验证当前用户拥有该项目及该日记。
- 标题和内容按纯文本渲染，不使用 `dangerouslySetInnerHTML`，避免 XSS。
- 后端限制标题、内容、图片数量、单图大小和扩展名；不能仅依赖前端校验。
- 删除操作不可仅依赖前端 `confirm`，API 必须再次执行归属校验。
- 网络错误、Token 过期、图片上传失败和保存失败均应显示用户可理解的错误信息。
- 图片清理必须跨日记、装修技巧、知识文章等引用来源检查，不能因为删除一篇日记而删除仍在使用的文件。

## 9. 实施步骤

### T1：现状核对与数据边界

读取采购阶段加载逻辑、项目切换逻辑、图片上传逻辑和数据库初始化逻辑；确认日记按项目隔离，不写入旧的本地同步结构。

### T2：后端模型、迁移与 Schema

新增 `RenovationDiary`、`DiaryCreate`、`DiaryUpdate`、`DiaryOut`，增加幂等建表迁移及项目关系。

### T3：后端路由与测试

实现列表、创建、更新、删除；覆盖项目隔离、搜索、阶段筛选、空内容、图片引用清理和未授权访问。

### T4：前端 API、类型与导航

增加日记 API 封装、类型、`/diary` 路由和辅助工具导航项；验证桌面侧栏、移动端导航及当前页面高亮。

### T5：页面列表与筛选

完成页头、数量统计、搜索、阶段筛选、加载态、错误态、空态和日记卡片。

### T6：新建/编辑弹窗与图片上传

完成表单校验、默认当天日期、采购阶段选择、图片上传预览、编辑回填、保存和删除。

## 10. 验收标准

### 功能验收

- [ ] 从辅助工具可以进入“装修日记”，路由为 `/diary`。
- [ ] 页面左上角显示“装修日记”，右侧显示当前项目日记总数量，右上角有“写日记”按钮。
- [ ] 下一行显示关键词搜索和阶段筛选，阶段选项与采购清单阶段分类一致。
- [ ] 日记列表按日期倒序显示，能看到标题、日期、阶段、内容摘要和图片信息。
- [ ] 点击“写日记”打开弹窗，字段顺序符合标题、日期、阶段、内容、图片、关闭/保存要求。
- [ ] 新建日记日期默认当天，阶段可以选择采购清单中的任一阶段。
- [ ] 标题、日期、阶段必填校验有效；保存期间不能重复提交。
- [ ] 图片支持上传、预览、删除，保存后刷新仍能正确显示。
- [ ] 编辑会回填全部字段，删除会二次确认且只删除当前项目日记。
- [ ] 搜索只匹配标题或内容，阶段筛选只匹配对应阶段，清除筛选后恢复完整列表。

### 数据与安全验收

- [ ] 不同项目之间的日记互不可见。
- [ ] 未登录用户不能通过 API 访问或修改日记。
- [ ] 用户不能操作其他用户项目的日记 ID。
- [ ] 删除日记时不会误删仍被其他功能使用的图片。
- [ ] 数据库重启后日记、图片 URL 和更新时间保持正确。

### 视觉与兼容性验收

- [ ] 在 1440px、1024px、768px、390px 和 320px 宽度下无横向溢出。
- [ ] 桌面侧栏和移动底部导航的“装修日记”当前状态正确。
- [ ] 新页面使用现有主题变量，切换主题后按钮、标签、焦点态仍清晰可辨。
- [ ] 键盘可以完成打开弹窗、填写表单、上传入口、保存、关闭和删除确认。
- [ ] 原有采购清单、装修技巧、流程和记账功能回归正常。

## 11. 建议测试用例

### 后端测试

1. 创建日记成功并返回完整字段。
2. 标题为空、日期为空、阶段为空时返回校验错误。
3. 搜索标题和搜索正文均能命中，其他内容不能命中。
4. 按采购阶段筛选只返回对应日记。
5. 项目 A 的用户不能读取、更新或删除项目 B 的日记。
6. 删除日记后，未被引用的图片文件被清理；仍被其他记录引用的图片保留。
7. 非法图片 URL、超长内容和过多图片被拒绝。

### 前端测试

1. 页面初始显示标题、统计数量、写日记按钮、搜索框和阶段筛选。
2. 打开新建弹窗时日期为当天，阶段选项来源于采购参考阶段。
3. 保存成功后列表和数量统计更新。
4. 编辑弹窗可以正确回填并保存修改。
5. 搜索、阶段筛选、清除筛选和空状态显示正确。
6. 上传失败不会清空已经上传的其他图片。
7. 遮罩关闭、Escape 关闭和未保存修改提示有效。
8. 窄屏弹窗和图片网格不溢出，键盘焦点顺序合理。
