# 装修手记主题更换功能开发文档

> 适用项目：装修手记（React 19 + TypeScript + Vite / FastAPI + SQLAlchemy）  
> 文档日期：2026-08-25  
> 本期范围：主题色（预设与自选）、桌面端/移动端布局选择、用户级持久化与“确认后生效”。

---

## 1. 目标与范围

在“我的”（`/account`）新增“主题与布局”入口，进入独立页面 `/theme-settings` 后，用户可暂存选择：

- 主题色：选择若干预设颜色，或通过调色盘选择自定义颜色；
- 桌面端布局：保留当前布局（`desktop-default`），并提供一种新布局（`desktop-focus`）；
- 移动端布局：保留当前布局（`mobile-default`），并提供一种新布局（`mobile-compact`）；
- 仅在用户点击“确定并应用”后，才将主题应用到全站并保存到数据库；
- 配置属于账号、与装修项目无关；同一账号在不同设备登录后应读取同一配置。

“后续再添加的另一种布局”不纳入本期 UI 与代码实现，但本方案会通过布局注册表和枚举校验预留扩展位，新增布局时无需改表结构或接口契约。

### 非目标

- 不按项目保存主题，不进入 `AppState`/项目同步接口；
- 不提供深色模式、字体更换；
- 不在未登录状态向服务端保存。未登录访问设置页时应提示先登录，并跳转 `/login`。

**后续独立功能说明：** 组件级拖拽排序属于某一业务页面自身的后续开发能力（例如用户在首页或其他指定页面内直接拖拽），不属于“主题与布局”设置页，也不应由本期主题偏好表保存。届时应根据具体页面和排序范围另行设计数据模型与交互。

## 2. 当前项目理解与设计结论

| 现状 | 相关实现 | 本功能的落点 |
|---|---|---|
| 全局主题主要由 CSS 变量控制 | `frontend/src/styles/design-tokens.css` 中 `--fresh-*` | 继续使用 CSS 变量；运行时覆盖派生变量，不重写各业务页面样式 |
| 部分颜色是硬编码 | `global.css`、`components.css`、页面内 `style` | 本期替换影响主题的硬编码色，保留状态色/语义色；详见第 6 节 |
| 壳层按 `<768px` 切换头部和底部导航 | `components/layout/AppShell.tsx` | 壳层读取用户主题，添加布局 class/data 属性并按设备渲染对应布局 |
| 首页结构固定为 `.home-pro` 三段网格 | `pages/HomePage.tsx`、`components.css` | 以布局注册表选择对应页面组合；本期可重排现有组件，后续布局可定义不同组件集合 |
| 已有 JWT、`/api/auth/me` 和用户表 | `backend/auth.py`、`models.py` | 新建用户级 `user_preferences`，所有接口从 token 获取用户，不接收 `user_id` |
| 项目数据已通过 `/api/projects/{id}/sync` 同步 | `data/store.ts`、`api/sync.ts` | 主题独立于项目同步，避免切项目、导入导出和登录迁移覆盖账号偏好 |

**归属决策：** 主题是用户全局偏好而非装修项目偏好，故以 `user_id` 作为唯一键。一位用户只能有一条偏好记录；切换项目不得改变主题。

## 3. 交互与页面设计

### 3.1 我的页面入口

在 `frontend/src/pages/AccountPage.tsx` 的“分类管理”卡片之前新增一张入口卡：

- 标题：`主题与布局`；
- 说明：`更换全站主题色及桌面/移动端页面布局`；
- 点击跳转 `/theme-settings`；
- 使用现有 `card`、入口卡排版与图标体系；可新增 `IconPalette`（或使用现有图标库中语义相近图标）。

该入口对登录用户可用。因页面已在 `ProtectedRoute` 内，实际未登录访问由受保护路由处理；页面组件仍须保留加载/错误态。

### 3.2 主题设置页 `/theme-settings`

新增 `frontend/src/pages/ThemeSettingsPage.tsx`，通过 `AppShell currentPage="theme-settings"` 承载。建议结构：

1. 页面标题：`主题与布局`，副标题“设置将与当前账号关联，在其他设备登录后自动同步”。
2. 主题色卡片：预设色选择区 + 自定义调色盘 + 小型效果预览。
3. 桌面端布局卡片：仅在宽度 `>= 768px` 时展示可操作控件；小屏显示“请在桌面端预览和选择”。
4. 移动端布局卡片：仅在宽度 `< 768px` 时展示可操作控件；桌面显示“请在移动端预览和选择”。
5. 页面底部固定/粘性操作栏：`取消`、`恢复默认`、`确定并应用`。

选择控件只更新页面内草稿 `draftPreference`。**不得**在颜色点选、布局卡点选时调用 `applyTheme()`，也不得请求保存接口。点击“确定并应用”后的顺序为：

1. 前端校验调色盘产出的颜色值；
2. 调用 `PUT /api/user-preferences/theme`；
3. 成功后调用 `applyTheme(savedPreference)` 并更新主题上下文；
4. 提示“主题设置已保存”，停留当前页；失败则保留草稿、显示错误，页面外观不变。

`取消`：放弃草稿并回到 `/account`，不发送请求。`恢复默认`：只重置草稿；仍需用户点击“确定并应用”才能保存。首次加载时，草稿来自服务端已保存值。

### 3.3 预设主题色

本期提供以下预设，均以主色 `primaryColor` 保存：

| id | 名称 | 主色 |
|---|---|---|
| `coral` | 珊瑚橙（默认） | `#E45B3F` |
| `jade` | 玉石绿 | `#3F8F70` |
| `ocean` | 海湾蓝 | `#3B82C4` |
| `violet` | 暮光紫 | `#7C5CC4` |
| `amber` | 琥珀金 | `#C98525` |
| `custom` | 自定义 | 调色盘选择值 |

- 自定义颜色使用原生 `<input type="color">` 或等效的可访问调色盘组件选择；不提供手工文本输入框；
- 调色盘输出统一规范化为大写 `#RRGGBB`；若组件异常产出非法值，则禁用“确定并应用”并给出中文错误；
- 选预设时设置 `colorMode='preset'` 和 `presetColorId`；使用自选色时设置 `colorMode='custom'`、`presetColorId=null`；
- UI 中的选中态不能只依赖 `primaryColor`，应同时识别模式，避免自定义色刚好与预设色相同导致语义混乱。

### 3.4 布局定义

当前首页为“默认布局”。本期新增布局可优先复用和重排已有组件；但“布局”是完整的页面呈现方案，**允许不同布局拥有不同的组件集合、组件层级和信息优先级**。后续布局开发可新增、隐藏或替换组件，具体内容以相应布局需求为准。

| 端 | id | 名称 | 内容组织 |
|---|---|---|---|
| 桌面 | `desktop-default` | 全景总览 | 保持当前 Hero 双列、三列进度区、主内容+右侧栏 |
| 桌面 | `desktop-focus` | 专注工作台 | 本期可将待办、预算等高频工作组件前置；具体包含哪些组件、是否新增组件，由该布局的后续视觉与产品设计确定 |
| 移动 | `mobile-default` | 卡片总览 | 保持当前首页移动端顺序和底部导航 |
| 移动 | `mobile-compact` | 紧凑清单 | 本期可优先呈现待办、待购、近期支出等移动端高频信息；组件增减、折叠与入口安排由该布局的后续设计确定 |

桌面与移动布局为独立字段：用户可在桌面选择桌面布局、在手机选择移动布局；保存同一份账号偏好时必须合并另一端原值，绝不能把未编辑的另一端重置为默认值。

## 4. 数据模型与迁移

### 4.1 SQLAlchemy 模型

在 `backend/models.py` 新增：

```python
class UserPreference(Base):
    __tablename__ = "user_preferences"
    __table_args__ = {"comment": "用户主题与布局偏好"}

    user_id = Column(String(36), ForeignKey("users.id"), primary_key=True)
    color_mode = Column(String(20), nullable=False, default="preset")
    preset_color_id = Column(String(30), nullable=True, default="coral")
    primary_color = Column(String(7), nullable=False, default="#E45B3F")
    desktop_layout = Column(String(40), nullable=False, default="desktop-default")
    mobile_layout = Column(String(40), nullable=False, default="mobile-default")
    updated_at = Column(DateTime, default=_now, onupdate=_now, nullable=False)

    user = relationship("User", back_populates="preference")
```

同时在 `User` 添加：

```python
preference = relationship("UserPreference", back_populates="user", uselist=False,
                          cascade="all, delete-orphan")
```

`Base.metadata.create_all` 会在新环境建表。生产已有库由现有 `backend/database.py::_migrate_integration` 增加幂等迁移：创建缺失表（推荐 `Base.metadata.tables['user_preferences'].create(conn, checkfirst=True)`），不修改或回填已有用户数据。读取时无记录即返回默认值；首次 `PUT` 再创建记录，因此无需为全部老用户预插数据。

### 4.2 后端 Schema

在 `backend/schemas.py` 增加：

```python
class ThemePreferenceUpdate(BaseModel):
    color_mode: Literal["preset", "custom"]
    preset_color_id: Literal["coral", "jade", "ocean", "violet", "amber"] | None = None
    primary_color: str = Field(..., pattern=r"^#[0-9A-Fa-f]{6}$")
    desktop_layout: Literal["desktop-default", "desktop-focus"]
    mobile_layout: Literal["mobile-default", "mobile-compact"]

class ThemePreferenceOut(ThemePreferenceUpdate):
    updated_at: datetime

    model_config = {"from_attributes": True}
```

在 Pydantic `model_validator(mode='after')` 追加一致性校验：`preset` 必须提供 `preset_color_id` 且其颜色与服务端常量一致；`custom` 必须为 `preset_color_id=None`。不要信任前端传来的预设色映射。

### 4.3 数据库约束与安全

- `user_id` 是主键，天然保证“一账号一配置”；
- 所有查询条件固定为 `UserPreference.user_id == current_user.id`；请求体不允许携带 `user_id`；
- 服务端再次使用 `^#[0-9A-Fa-f]{6}$` 校验颜色，且只允许声明的布局 id，避免任意 class/CSS 注入；
- 主题数据无敏感信息，不写入项目导出 JSON，也不影响已有同步和清空本地项目缓存逻辑。

## 5. API 设计

新建 `backend/routers/user_preferences.py`，前缀 `/api/user-preferences`，两个接口都使用 `Depends(get_current_user)`。在 `backend/main.py` 导入并注册 router。

| 方法 | 地址 | 说明 | 返回 |
|---|---|---|---|
| GET | `/api/user-preferences/theme` | 获取当前账号偏好；无记录时返回默认对象，不落库 | `ThemePreferenceOut` |
| PUT | `/api/user-preferences/theme` | 原子创建或完整更新当前账号配置 | `ThemePreferenceOut` |

实现原则：

```python
@router.get("/theme", response_model=ThemePreferenceOut)
async def get_theme_preference(user=Depends(get_current_user), db=Depends(get_db)):
    preference = await db.get(UserPreference, user.id)
    return preference or DEFAULT_THEME_PREFERENCE

@router.put("/theme", response_model=ThemePreferenceOut)
async def update_theme_preference(data: ThemePreferenceUpdate, user=Depends(get_current_user), db=Depends(get_db)):
    validate_theme(data)  # 服务端常量、模式与颜色的一致性检查
    preference = await db.get(UserPreference, user.id)
    if preference is None:
        preference = UserPreference(user_id=user.id, **data.model_dump())
        db.add(preference)
    else:
        for field, value in data.model_dump().items():
            setattr(preference, field, value)
    await db.commit()
    await db.refresh(preference)
    return preference
```

未认证请求沿用全局鉴权行为返回 `401`；其他用户无法通过 URL 或 body 访问/修改本用户配置以外的记录。

## 6. 前端架构与样式改造

### 6.1 类型、API 与状态边界

新增以下文件：

- `frontend/src/data/theme.ts`：前端 `ThemePreference`、预设元数据、默认值、颜色校验/规范化和派生颜色函数；
- `frontend/src/api/userPreferences.ts`：`fetchThemePreference()`、`updateThemePreference()`，复用 `apiGet`、`apiPut`；
- `frontend/src/components/theme/ThemeProvider.tsx`：加载、应用、刷新用户主题的 Context/Hook；
- `frontend/src/pages/ThemeSettingsPage.tsx`：设置页；
- 可选 `frontend/src/components/theme/ThemePreview.tsx`：颜色和布局缩略预览，避免设置页过大。

不要把主题字段加入 `AppState` 或 `store.ts`：该 store 当前服务于本地项目状态与 `/sync`，而主题属于账号级资源。`ThemeProvider` 在 `App` 的 `BrowserRouter` 内、路由外包裹；在认证状态完成后 GET 一次，在登出时立即 `resetThemeToDefault()`，以避免前一账号的视觉配置泄漏到下一账号。

`ThemeProvider` 推荐状态：

```ts
type ThemeContextValue = {
  preference: ThemePreference;
  loading: boolean;
  error: string | null;
  applyTheme: (preference: ThemePreference) => void;
  refreshTheme: () => Promise<void>;
};
```

### 6.2 CSS 变量应用方式

在 `design-tokens.css` 保留默认值，并增加由主题主色驱动的语义变量，例如：

```css
:root {
  --theme-primary: #E45B3F;
  --theme-primary-deep: #C94F36;
  --theme-primary-soft: #FFF0EA;
  --theme-primary-ring: rgba(228, 91, 63, .12);
  --theme-primary-shadow: rgba(228, 91, 63, .17);

  --fresh-coral: var(--theme-primary);
  --fresh-coral-deep: var(--theme-primary-deep);
  --fresh-coral-soft: var(--theme-primary-soft);
}
```

`applyTheme` 通过 `document.documentElement.style.setProperty()` 写入上述 5 个变量，并设置：

```ts
document.documentElement.dataset.desktopLayout = preference.desktopLayout;
document.documentElement.dataset.mobileLayout = preference.mobileLayout;
```

派生色须由代码按 HSL/OKLCH 计算，至少生成深色、浅色、focus ring 和阴影透明色；不要仅把 `primaryColor` 替换进现有 `rgba(228, 91, 63, ...)` 字符串。这样自选颜色才会在 hover、焦点与背景上保持可读性。

将主题相关的硬编码珊瑚色（如 `#e45b3f`、`rgba(228, 91, 63, ...)`、`#fff5ef`）替换为语义变量。成功/警告/危险状态色 `--fresh-green`、`--fresh-amber`、红色删除态仍保持固定，不能被主题色误替换。页面中零散的 `var(--color-primary)`、`--fresh-border`、`--fresh-surface` 应统一为已有 token 或补齐兼容 alias，避免切换后出现变量未定义。

### 6.3 布局实现

`AppShell` 仍可用 `isMobile` 选择 `DesktopHeader/MobileHeader`；布局选择由根节点的 `data-*` 属性和对应布局组件共同决定。对于仅涉及网格的布局，可通过 CSS media query 覆盖；对于组件集合或层级不同的布局，应在页面层按布局 id 选择独立的布局组合组件（如 `DesktopFocusHomeLayout`），这些布局组件复用业务卡片与数据 Hook，但不强制沿用默认布局的 DOM 结构。

示意：

```css
@media (min-width: 768px) {
  :root[data-desktop-layout="desktop-focus"] .home-pro > .live-widgets {
    grid-template-columns: 1fr 1fr;
  }
  :root[data-desktop-layout="desktop-focus"] .home-pro > .layout {
    /* 对仅调整排列的布局，可通过 grid-area 重排现有组件 */
  }
}

@media (max-width: 767px) {
  :root[data-mobile-layout="mobile-compact"] .home-pro {
    gap: 10px;
    width: min(100% - 20px, 680px);
  }
}
```

若布局需要改变 DOM 阅读顺序或组件集合，在页面层选择对应布局组件，而不是滥用 CSS `order`，以保证视觉顺序、键盘顺序与读屏顺序一致。同一布局实例中，业务组件只能在一个位置渲染一次；不同布局之间则可按各自需求选择是否渲染该组件。

### 6.4 路由与导航

- `App.tsx` 在受保护路由内增加 `<Route path="/theme-settings" element={<ThemeSettingsPage />} />`；
- `AccountPage.tsx` 新增入口；
- `DesktopHeader` 和 `MobileBottomNav` 不将“主题与布局”设为一级导航；它仅从“我的”进入；
- `AppShell` 在设置页仍按实际屏宽显示相应导航，`currentPage` 可使用 `theme-settings`，不需要添加导航高亮。

## 7. 加载、保存与异常时序

```text
应用启动 → useAuth 验证 token
  ├─ 未登录：ThemeProvider 应用默认主题，不请求主题 API
  └─ 已登录：GET /api/user-preferences/theme
       ├─ 成功：校验后 applyTheme(服务端配置)
       └─ 失败：保留默认主题，显示非阻塞提示，可在设置页重试

进入设置页 → 读取当前已应用配置作为草稿 → 用户修改草稿
  ├─ 取消：丢弃草稿，返回我的页面
  └─ 确定并应用 → PUT 完整配置 → 成功后 applyTheme + 提示成功
                                  └─ 失败：不应用、不跳转、保留草稿与错误提示

退出登录 → resetThemeToDefault() → 清除内存主题状态
```

为避免主题加载闪烁，默认主题必须就是当前珊瑚橙方案。认证完成后再覆盖 CSS 变量；不要阻塞首屏，也不要把用户主题存进长期 `localStorage` 作为真值。若需要短期优化闪烁，可用 sessionStorage 缓存“上次已验证主题”，但启动仍应以服务端返回为准，且登出立即清除。

## 9. 测试与验收

### 后端测试

- 未登录 GET/PUT 返回 401；
- 新用户 GET 得到默认配置且数据库不产生重复记录；
- PUT 首次创建，二次 PUT 更新同一 `user_id`；
- 用户 A 无法读取/修改用户 B 的设置；
- 拒绝非法颜色、未知 preset、未知 desktop/mobile layout、模式与 preset 不一致的请求；
- 已存在业务数据和项目同步不受迁移影响。

### 前端测试/手工验收

- 默认主题与改造前视觉一致；预设五色均能影响按钮、链接、选中态、输入焦点、渐变/阴影；
- 调色盘选择值能规范化为大写 `#RRGGBB`，异常的非法值不能提交；
- 修改任一选项后不点确定，切换页面/取消后全站主题和数据库都不变；
- 确定成功后无需刷新立即生效；刷新页面、重新登录、另一设备登录同账号都保留；切换装修项目不改变设置；
- 登录不同账号时分别加载各自设置；退出登录立即回到默认主题；
- 宽度 767px/768px 两侧分别验证移动/桌面布局；各布局中已纳入的模块可正常操作，关键业务功能入口按该布局设计可达，键盘 Tab 顺序合理；
- 默认、新桌面、新移动布局下检查 320px、375px、768px、1024px、1440px，无横向滚动、无底部导航遮挡；
- 主题 API 网络失败时不误应用草稿，用户可看到明确错误并重试；
- 运行 `npm run build`、`npm run lint` 和后端 pytest（新增偏好接口用例）。

### 完成标准

功能完成应同时满足：设置入口可达；确认前不生效；确认后全站生效且与账户持久绑定；现有默认布局可用；本期新增的桌面与移动布局均可选择；服务端权限、参数校验和迁移均通过测试；并且新增下一种布局只需在前后端布局注册表/样式中增加 id，不需修改数据表。
