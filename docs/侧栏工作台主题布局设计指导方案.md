# 侧栏工作台主题布局设计指导方案

> 适用范围：装修手记桌面端（React + TypeScript）  
> 设计目标：以 `参考html/主页.html`、`装修流程.html`、`装修记账.html`、`比价选品.html`、`采购清单.html` 的共同工作台结构为参考，新增一套可切换的桌面端布局；不替换现有布局，也不改变既有业务数据和操作规则。

## 1. 结论与范围

新增桌面端布局，ID 固定为 `desktop-sidebar-workbench`，名称为“侧栏工作台”，说明为“左侧导航、顶部页头与页面工作区”。原“专注工作台”不再保留。

它与现有布局的关系如下：

| 布局 ID | 名称 | 适用范围 | 是否保留 |
| --- | --- | --- | --- |
| `desktop-default` | 全景总览 | 当前桌面端顶部导航和默认首页编排 | 保留，默认值不变 |
| `desktop-sidebar-workbench` | 侧栏工作台 | 全部桌面业务页面的壳层与页面内容组织 | 新增 |

移动端布局不在本次改造范围内：小于 `768px` 时仍按现有 `mobile-default` 或 `mobile-compact` 渲染，不出现桌面左侧栏。主题色仍复用当前 `ThemeProvider` 的 CSS 变量机制，布局切换不得重置用户已经选择的颜色。

参考文件的价值在于它们共享的桌面工作台框架，而不是逐页复制 HTML、品牌内容或外部链接。实现应复用本项目已有的数据、路由、组件和权限模型。

## 2. 从五个参考页面提炼的设计语言

五页均采用“稳定导航，内容随任务变化”的布局。应保留以下特征：

1. 左侧为固定工作区导航，按“装修工作区”和“辅助工具”分组；当前页面有明显的浅主题色底和主色文字。
2. 主区域顶部为轻量页头：上方显示面包屑/业务域，下方显示页面标题；右侧放本页最高频的一个主操作，搜索仅在确有全页检索能力时保留。
3. 内容区使用宽松的卡片工作台：浅暖灰背景、白色卡片、12px 圆角、弱边框和低对比阴影；强调色只用于主操作、选中、关键数值和当前流程。
4. 每页先给“状态与下一步”，再给“编辑、明细或资料库”；不把全部筛选、表单和明细同时推到首屏。
5. 列表页使用页内标签、汇总数字、筛选条、折叠分组和底部批量操作；流程页使用路线、当前节点和详情的连续阅读顺序。

| 参考页 | 应吸收的布局方法 | 在本项目中的落点 |
| --- | --- | --- |
| 主页 | 欢迎/今日重点、四项核心指标、施工路线与最近动态并列 | `HomePage`：保留已有数据卡，新增“今日优先事项”与阶段路线的首屏双栏组织 |
| 装修流程 | 进度摘要、横向阶段路线、当前阶段详情和攻略/验收分栏 | `FlowPage`：先展示当前/下一节点，再展示步骤、知识与操作 |
| 装修记账 | 月度或累计概览、支出统计、筛选和记账表单的主从结构 | `ExpensePage`：关键金额摘要置顶，筛选紧邻明细，录入操作固定在页头或抽屉 |
| 比价选品 | 比价对象汇总、筛选、方案/报价分层、采用方案的明确收口 | `ComparePage`：保留现有展开模型和报价能力，整理为“物品 → 型号 → 渠道报价”三级卡片 |
| 采购清单 | “我的待购 / 采购参考库”双视图、数量摘要、搜索、按施工阶段折叠 | `PurchasePage`：保留待购/已购和参考库，采用清晰的页内标签、摘要和分组 |

## 3. 新布局的壳层规范

### 3.1 桌面结构

在 `>= 768px` 且 `desktopLayout === 'desktop-sidebar-workbench'` 时，`AppShell` 使用新壳层：

```text
┌──────────────── 左侧栏 248px ────────────────┬──────────── 内容区 ────────────┐
│ 品牌 / 产品名                                 │ 面包屑 / 业务域      [主操作] │
│ 项目切换器                                    │ 页面标题                         │
│                                               ├───────────────────────────────┤
│ 装修工作区                                    │ 页面摘要、标签、筛选、业务卡片 │
│  · 今日总览  · 装修流程                       │                               │
│  · 采购清单  · 装修记账  · 比价选品          │                               │
│                                               │                               │
│ 辅助工具                                      │                               │
│  · 实用工具  · 装修技巧                      │                               │
│                                               │                               │
│ 底部：同步状态 / 账号菜单                     │                               │
└───────────────────────────────────────────────┴───────────────────────────────┘
```

尺寸与行为：左栏宽 `248px`，固定在视口左侧；右侧内容最小宽 `0`、最大内容宽 `1440px`，内边距 `28px 32px 48px`。顶栏高度 `72px`，在内容区顶部粘连。页面本身滚动，左栏和顶栏保持可见。`768–1099px` 允许左栏收窄至 `208px`、隐藏次要说明文字；小于 `768px` 完全回退现有移动壳层。

不要在新壳层同时渲染现有 `DesktopHeader`，避免双导航。项目切换、账号菜单、同步状态等已有能力需抽成可复用组件，由旧顶部导航和新侧栏共同消费，不能复制两套状态。

### 3.2 左侧栏信息架构

导航必须继续使用现有路由，顺序建议为：首页、装修流程、采购清单、装修记账、比价选品、实用工具、装修技巧、我的。当前项以 `aria-current="page"` 标识；点击后路由跳转，不因布局而改变页面地址。

侧栏顶部显示当前项目名称和切换入口；“主题与布局”仍属于“我的”页面的二级设置入口，不放入装修工作区主导航，避免与业务任务混淆。侧栏底部显示账号入口和同步/加载状态，离线或失败状态必须有文字而不能只用颜色。

### 3.3 页面页头

新增 `WorkbenchPageHeader`，通过 `AppShell` 或各页面传入 `eyebrow`、`title`、`primaryAction`、`secondaryActions`。

| 页面 | 业务域 / 标题 | 页头主操作 |
| --- | --- | --- |
| 首页 | 我的装修 / 装修总览 | 新增待办 |
| 流程 | 我的装修 / 装修流程 | 查看当前阶段攻略（没有当前阶段时隐藏） |
| 采购 | 我的装修 / 采购清单 | 新增待购物品 |
| 记账 | 我的装修 / 装修记账 | 记一笔 |
| 比价 | 我的装修 / 比价选品 | 新增比价物品 |
| 我的 | 我的 / 个人设置 | 无或保留与本页相关操作 |

主操作不可只依赖颜色区分；按钮须有可读文本、焦点态和禁用态。全局搜索不在第一期强行展示：没有跨模块搜索数据源时，保留各业务页现有筛选/搜索即可。

## 4. 各页面布局指导

### 4.1 首页：行动优先的项目工作台

首屏采用 7:5 双栏：左侧“问候 + 当前阶段 + 三个快捷入口”，右侧“今日优先事项”。其下为四个等宽指标：当前进度、预算余额、未完成待办、待购材料。再下方采用 8:4 双栏，左侧为施工路线/进度，右侧为最近动态或预算/采购摘要。

现有 `ReminderCard`、`TodayFocus`、`ProgressCard`、`StageRoute`、`BudgetPanel`、`TodoPanel`、`PurchaseSummary`、`ExpenseSummary` 必须复用；新布局只改变容器组合和信息优先级。任何组件在同一次渲染中只能出现一次，避免同一待办或预算在多个区域重复。

### 4.2 流程：当前节点驱动的连续阅读

上部依次为：完成率与当前/下一阶段摘要、横向阶段路线、当前阶段行动条。下部采用 7:5 双栏：左栏为步骤清单和节点说明，右栏为攻略、验收要点、相关知识和备注。宽度不足时先纵向堆叠，不用 CSS `order` 改变键盘阅读顺序。

### 4.3 采购：任务清单与参考库分离

保留“我的待购 / 采购参考库”作为页内 Tabs，切换不更改布局偏好。待购视图首行给待处理、已购买、总物品三项摘要；接着是筛选与清单；每条物品提供去比价、标记已购、删除等上下文操作。参考库视图先放搜索和新增物品，再以施工阶段折叠呈现。批量展开/收起放在搜索和分组之间。

### 4.4 记账：先判断，再录入

顶部显示预算、已付、待付/退款等不超过四项的摘要；其次为分类或阶段分布；账单列表之前放日期、状态、分类等筛选。新增/编辑账单使用抽屉或模态框，避免在桌面端常驻大表单挤压明细。金额颜色保持语义固定：收入/退款、预警、危险等不跟随主题主色。

### 4.5 比价：从选择到采购的闭环

顶部先显示“比价中物品、候选方案、已选最优方案”等摘要及筛选；物品卡片内部按“物品 → 型号 → 渠道报价”展开，最优报价和已采用状态有明确标签。页面底部或筛选栏下方提供常驻的“已选方案汇总”和“采用并加入采购”操作，但不得遮挡内容或在无选择时误导用户。

## 5. 在“我的 - 主题与布局”中切换

`/theme-settings` 的桌面端布局区域保留“全景总览”，并以“侧栏工作台”替换原“专注工作台”单选卡：

| 字段 | 值 |
| --- | --- |
| `id` | `desktop-sidebar-workbench` |
| 名称 | 侧栏工作台 |
| 说明 | 左侧导航、顶部页头与页面工作区，适合持续管理装修项目 |
| 缩略图 | 体现左栏、顶栏、四项摘要和内容卡片；不需要真实数据 |

两个布局卡都应显示名称、说明、简略线框图和单选状态。用户点击卡片时，只修改 `draftPreference.desktopLayout` 和设置页内的缩略预览；不得即时改变全站壳层或调用保存接口。点击“确定并应用”后，按既有流程保存成功再 `applyTheme(savedPreference)`；失败时留在设置页并保留草稿。切换回“全景总览”必须立即恢复当前桌面顶部导航壳层，业务路由、项目选择和数据不变化。

## 6. 技术落地边界

### 6.1 类型、接口与持久化

1. `frontend/src/data/theme.ts`：将 `DesktopLayoutId` 收敛为 `desktop-default` 与 `desktop-sidebar-workbench` 两个合法值，并在 `DESKTOP_LAYOUTS` 以侧栏工作台替换专注工作台元数据；不要把布局偏好写入项目 `store.ts`。
2. `backend/schemas.py`：`VALID_DESKTOP_LAYOUTS`、`ThemePreferenceUpdate.desktop_layout` 的 `Literal` 同步增加该 ID。
3. `backend` 的默认值仍为 `desktop-default`，现有 `user_preferences.desktop_layout VARCHAR(40)` 长度足够，不需要表结构迁移。旧用户读取后保持原布局，只有主动保存新选择才写入新 ID。
4. API 响应映射和服务端校验必须只接受白名单 ID，禁止将任意字符串直接写入 `data-desktop-layout`。
5. 为 schema/API 增加新 ID 的成功用例，以及未知 ID 的拒绝用例；前端增加切换后 `AppShell` 选中正确壳层的测试。

### 6.2 组件建议

新增而非复制业务逻辑：

```text
components/layouts/
  DesktopSidebarWorkbenchShell.tsx   # 仅桌面壳层
  WorkbenchSidebar.tsx               # 导航、项目、账号入口
  WorkbenchPageHeader.tsx            # 页面标题与主操作
  workbenchNavigation.ts              # 单一导航配置源
components/layouts/
  DesktopSidebarWorkbenchHomeLayout.tsx
```

`AppShell` 负责依据 `useTheme().preference.desktopLayout` 选择 `DesktopHeader` 或 `DesktopSidebarWorkbenchShell`。各页面只负责传递当前页面与页头动作，并在需要时选择新的内容组合；不要在每一个页面自行判断布局后复制导航 DOM。

现有首页组件的 `window.innerWidth` 判断应改为可监听的响应式 Hook 或由 `AppShell` 提供的设备信息，确保调整浏览器宽度时可以正确在桌面、平板和移动壳层之间切换。

### 6.3 样式令牌与可访问性

新增布局样式放在独立的 `workbench-layout.css` 或清晰的组件样式区，并以 `:root[data-desktop-layout="desktop-sidebar-workbench"]` 为作用域。继续使用 `--theme-primary`、`--theme-primary-soft`、`--fresh-*` 等语义变量；不得把 `#E45B3F` 写入新布局样式。

侧栏和顶部页头应有可见焦点样式；小于 1100px 时导航文字缩短或折叠，但可访问名称不可丢失；在 200% 缩放和键盘 Tab 导航下，主内容必须先于不相关的装饰内容可操作。卡片对比度、文本与背景对比度、选中态不能仅靠色相区别。

## 7. 分阶段实施与验收

1. 更新布局注册、后端白名单与测试，并在主题与布局页以侧栏工作台替换原专注工作台卡片。
2. 完成新桌面壳层、共享导航和页头；先接入首页、流程、采购、记账、比价五页，其他页面可使用同一壳层加默认页头。
3. 逐页按第 4 节重组内容容器，复用现有业务组件和状态逻辑。
4. 在 `1440px`、`1024px`、`768px`、`390px` 验证：全景总览与侧栏工作台两种桌面布局可反复切换；刷新/重新登录后保留选择；切换项目不改变布局；移动端不渲染侧栏；五页的新增、筛选、展开、比价、采购、记账等现有操作均可用。

验收完成标准：新布局可在“我的 - 主题与布局”保存并跨设备读取；全景总览保持原有外观和功能；侧栏工作台在五个目标页面均有一致的导航、页头和内容节奏；任何主题颜色下选中态、按钮、焦点态和状态色都清晰可辨。
